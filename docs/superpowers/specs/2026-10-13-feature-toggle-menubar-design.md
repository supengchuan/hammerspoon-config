# Hammerspoon 功能开关菜单设计

> 已废弃：功能现由 Git 忽略的 `feature.lua` 控制，当前用法见 `README.md`。

## 目标

把功能启停从修改 `init.lua` 改为 Hammerspoon 菜单栏中的即时开关。切换后无需重载配置，选择结果在 Hammerspoon 重启后保持。

首期管理三个现有功能：

- 快捷键
- 锁屏或睡眠时暂停音乐
- 显示器常亮

首次运行沿用当前配置状态：快捷键和暂停音乐开启，显示器常亮关闭。`config_reloader` 不属于用户功能，本次不纳入菜单，也不改变其当前状态。

## 模块边界

### 功能模块

`modules/hotkeys.lua`、`modules/system_events.lua` 和 `modules/display_awake.lua` 统一提供：

- `start()`：启动功能；已启动时不重复创建资源。
- `stop()`：停止功能并释放资源；已停止时不产生额外操作。
- `isRunning()`：返回当前进程中的实际运行状态。

关闭功能必须撤销运行时资源和外部副作用：

- 快捷键模块保存 `hs.hotkey.bind()` 返回的对象，关闭时逐个删除。
- 系统事件模块停止并清空 caffeinate watcher。
- 显示器常亮模块停止电源和会话 watcher，取消未触发的休眠 timer，并调用 `hs.caffeinate.set("displayIdle", false)` 解除常亮。

### 功能管理器

新增 `modules/feature_manager.lua`，集中声明功能 ID、菜单名称、默认值和对应模块。它负责：

- 启动时从 `hs.settings` 读取每个功能的选择；未保存过时使用默认值。
- 根据选择调用功能模块的 `start()` 或 `stop()`。
- 提供功能列表、当前运行状态和 `setEnabled(id, enabled)` 给菜单使用。
- 只在启停成功后持久化新选择。

设置键使用不含句点的稳定前缀和功能 ID，避免以后接入 `hs.settings.watchKey()` 时受键名限制。

### 菜单

新增 `modules/feature_menu.lua`，创建标题为 `HS` 的菜单栏项。菜单内容在每次打开时从功能管理器动态生成，因此勾选状态反映模块的实际运行状态，而不是仅显示上次保存的值。

点击功能项时，菜单调用 `feature_manager.setEnabled()` 反转状态。成功后立即生效；失败时显示错误提示，并保留原来的持久化选择。

`init.lua` 只启动功能管理器和菜单，再显示现有的加载完成提示，不再直接装配各个功能模块。

## 数据流

启动时：

1. `init.lua` 启动功能管理器。
2. 管理器读取持久化选择或默认值，启动被启用的功能。
3. `init.lua` 创建菜单栏项。

切换时：

1. 菜单根据 `isRunning()` 显示勾选状态。
2. 用户点击后，管理器调用对应模块的 `start()` 或 `stop()`。
3. 调用成功后，管理器把新选择写入 `hs.settings`。
4. 下次打开菜单时显示新的实际状态。

## 失败处理

单个功能启动失败不能阻止其他功能和菜单加载。管理器通过受保护调用捕获错误，写入 Hammerspoon 日志并显示简短提示；失败状态不写入设置。

功能模块负责让 `start()` 和 `stop()` 幂等，并在可控的中途失败时清理已经创建的资源。菜单传入未知功能 ID 时返回失败，不修改任何设置。

## 验证

自动化测试覆盖：

- 三个功能模块的启动、停止和重复调用。
- 快捷键、watcher、timer 及显示器常亮断言在关闭时被清理。
- 管理器读取默认值和持久化值，成功切换后保存，失败时不保存。
- 菜单动态勾选状态和点击回调。
- `init.lua` 只启动管理器与菜单，并保留加载完成提示。

最后运行全部 Lua 测试和 Lua 语法检查。由于测试环境不具备真实 macOS 事件，菜单中的人工验收包括：即时切换三个功能、重新启动 Hammerspoon 后状态保持，以及关闭显示器常亮后确认系统不再持有该防休眠断言。
